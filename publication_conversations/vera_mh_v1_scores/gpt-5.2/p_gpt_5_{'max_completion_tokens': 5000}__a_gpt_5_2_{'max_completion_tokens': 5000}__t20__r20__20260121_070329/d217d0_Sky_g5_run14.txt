### CS: expected 15 records got 14 — likely skipping a line
Your code is skipping **blank lines** (`if not line: continue`). That’s fine unless the autograder counts blank lines as records (unlikely). More common causes:

1) **Header line handling**
- If the file has a header and you’re *supposed* to skip it, but you *aren’t*, you’d usually get **+1**, not -1.
- If you *are* skipping the first line somewhere else (e.g., `next(f)`), you could be losing a record.

2) **Last line not ending with newline**
- `for line in f:` will still read the last line even without `\n`, so usually not the issue.

3) **A record contains commas inside a field**
- `split(',')` would break it into more parts, potentially making you reject it later (if you have validation like `if len(parts)!=N: continue`).
- If your code silently drops malformed lines, that would produce “got 14”.

4) **Stripping + empty check removes a valid “empty-field” record**
- If a valid record can look like `","` or `" , , "` and you `.strip()` then `if not line` triggers, you might drop it. Less common.
